1. Installation and Verification

Download Bolt from the official portal (docs-first distribution). The Download page lists signed artifacts and checksums you should verify.

swifteexstudio.github.io/Swifteex/downloadbolt.html

Verify installation

After installing, check the runtime version to confirm the binary is accessible and to view build info.

bolt --version

If bolt is not recognized, run it directly from the download folder. On Windows, open the folder, type cmd in the File Explorer address bar and run the version command there.

2. Command Line Interface (CLI)

Key runtime flags. Combine them for the desired behavior.

  • --run [files...] — execute one or more .blt files.
  • --exec-string "<source>" — run a code string from the shell.
  • --cmd — quick single-line interactive mode.
  • --safe — sandbox mode: disables unsafe built-ins (e.g. input, sleep).
  • --debug — verbose logging with full tracebacks.
  • --inspect-ast — print AST before execution (diagnostics).
  • --json-errors — format errors as JSON for automation.
  • --no-type-warn — suppress type-related warnings at runtime.
bolt --safe --debug --run myscript.blt

Tip: use --json-errors when integrating Bolt into CI pipelines or automated tooling so parsing is reliable.

3. Language Reference — highlights

Core keywords and frequently-used built-ins. See full spec on the distribution portal for the complete API.

Keywords

Compact aliases are available for productivity:

  • Functions: fn, ret
  • Conditionals: if, el, esl
  • Loops: wh/whl (while), fr/for, br (break), nx (next)
  • Logic: not, and, or
⚠️ Notice: Some parts of the language examples may not work properly in Bolt. We are actively fixing it.

Built-ins (common)

  • IO: print, prnt, input (disabled in --safe).
  • Memory: alloc(size), free(ref), memcpy(dst, src, n), memset(dst, val, n), heap_view().
  • Math & Time: sin, cos, sqrt, pow, rand, randint, time, sleep (sleep disabled in safe mode).
  • Collections: len, range, list, dict, uniq.

4. Tutorials (copy-ready)

Small, focused examples. Copy each snippet with the button provided. Note: `let.userinput` and `let.call` are CORE-only features — they exist only in Bolt CORE builds. If you are running the stable (non-CORE) runtime, use the standard `input()` or `bolt` interactive features shown in the fallback examples below.

CORE-only: interactive function example (corrected)

/* CORE-only: uses let.userinput and let.call */
fn hi() ;;
  name = let.userinput("name: ");
  prnt("hi there, " + name + "!");
  age = let.userinput("age: ");
  prnt("you are " + age + " years old!");
  favfood = let.userinput("what is your favourite food? ");
  prnt("hi there, " + name + ". You are " + age + " years old and you like " + favfood + ".");
  ret;
;;;

let.call hi();

Explanation (CORE):

  • fn ... ;; ... ;;; — function definition with the `;;`/`;;;` block markers used in examples elsewhere in this docset.
  • let.userinput(prompt) — CORE-only input helper that returns the entered string. Use only on CORE builds.
  • let.call fnName() — CORE-only function-invocation helper (invokes a previously defined function).
  • prnt(...) — shorthand print (alias for the standard print built-in).

CORE-only: a guarded price example

/* CORE-only: simple decision using let.userinput */
fn price() ;;
  pizza = 100;
  burger = 500;
  choice = let.userinput("eat (pizza/burger): ");
  if (choice == "pizza") {
    prnt("that will be " + pizza + " dollar");
  } else if (choice == "burger") {
    prnt("that will be " + burger + " dollar");
  } else {
    prnt("unknown option: " + choice);
  }
  ret;
;;;

let.call price();

Non-CORE fallback (stable runtime)

/* Stable (non-CORE) fallback using built-in input() and direct calls */
fn hi() ;;
  name = input("name: ");
  prnt("hi there, " + name + "!");
  age = input("age: ");
  prnt("you are " + age + " years old!");
  favfood = input("what is your favourite food? ");
  prnt("hi there, " + name + ". You are " + age + " years old and you like " + favfood + ".");
  ret;
;;;

/* Call the function directly in stable builds */
hi();

Honest notes:

  • If you intend to ship interactive scripts to users who may run stable (non-CORE) Bolt, include both paths (CORE and fallback) or detect the runtime and choose the supported API at runtime. CORE-only helpers will fail on stable builds.
  • Prefer explicit validation of user inputs (e.g., check that age parses as a number) before using them in production scripts.
  • Function markers in examples (`;;` / `;;;`) are used consistently in this docset — keep them when authoring Bolt source files to match the examples shown here.

If you run the CORE build named boltcr the version output should look like the sample below. This verifies you are running the CORE variant and shows licensing/build metadata.

C:\Users\user>boltcr --version
Bolt Runtime Engine v1.6.0+1 (V: offical=false/core) . licensed commercial use only
Copyright © 2026 Swifteex (a HyperClouD Softwares company). All rights reserved.
2026-01-28

Note: The "core" marker in the version string is the primary signal your binary is a CORE build. Stable Bolt builds will omit the (.../core) marker or display a different official flag.
