Command Line Interface

Flags and runtime modes in Bolt. Combine them to fit your workflow.

  • --run [files...] - execute .blt files
  • --exec-string "<source>" - run inline source
  • --cmd - single-line interactive mode
  • --safe - sandbox mode (blocks interactive and unsafe built-ins)
  • --debug - verbose logging and tracebacks
  • --inspect-ast - print AST before execution for diagnostics
  • --json-errors - machine-readable error output for CI
bolt --safe --debug --run myscript.blt

New Syntax - v1.61+ Quick Reference

This section focuses on syntax and features available from Bolt v1.61+. Typed input helpers and modern flow constructs are available in v1.61 and newer.

Printing - sys.out

What it is and what it does: sys.out writes text or evaluated tokens to standard output. Use forward slashes to expand variables inside output: /var/. Numeric expressions are evaluated when tokens are numeric.

sys.out'hello, world!'
name = 'Ariyan'
sys.out /name/

num1 = 10
num2 = 15
sys.out /num1/ + /num2/
sys.out'the calculation is /num1 + num2/'

If you see literal tokens such as "/name/" in output, confirm the variable is defined and that you used forward slashes without spaces.

Variables

Assignment uses equals. Starting with v1.61+ integers and numeric types are available and usable in arithmetic.

myvariable = 'Alice'
age = 11
sys.out /myvariable/
sys.out /age/

For values coming from user input, prefer the typed input helpers below to ensure numeric types.

Lists

Create lists with let.list['a' ; 'b']. Index with 0-based notation: mylist[0].

mylist = let.list['bob' ; 'john']
sys.out /mylist[0]/
sys.out'hi /mylist[0]/!'

Guard indexes with len() to avoid out-of-range errors as shown below.

idx = 0
if (len(mylist) > idx)
  sys.out /mylist[idx]/
else
  sys.out'index out of range'
end.if

Functions and invocation

Functions are declared with fn name(); ... end. The helper let.call name() is available and standard on v1.61+. Many stable runtimes also allow direct invocation such as name().

fn greet();
  sys.out'hello from greet'
end

let.call greet()

Make sure functions are defined before invoking them, or call at runtime after the definition section.

Typed input helpers (v1.61+)

In v1.61+ Bolt provides typed input helpers to capture typed values directly: let.userinput.int'prompt' for integers and let.userinput.str'prompt' for strings. These reduce bookkeeping and parsing in common interactive scripts.

num = let.userinput.int'enter a number: '
name = let.userinput.str'enter your name: '

If you need to support older runtime versions, detect version via bolt --version and fall back to parsing raw input where necessary.

Control flow - if, eif, else

v1.61+ includes the familiar conditional ladder: if, eif for else-if, and else for fallback. Use end.if to close the block.

if condition
  sys.out'yes'
eif other_condition
  sys.out'other'
else
  sys.out'no'
end.if

Always validate types when doing numeric comparisons. Use tonumber() or typed input helpers to guarantee numeric comparisons.

Calculator Example - Full Breakdown (v1.61+)

The calculator example below assumes Bolt v1.61+ so that typed input helpers and modern control flow are available. The example is split into parts with precise, testable fixes and fallback suggestions for older runtimes.

Canonical source

fn calc();
  sys.out'welcome to calc.'
  num1 = let.userinput.int'enter number first: '
  num2 = let.userinput.int'enter number second: '
  sys.out'1) addition 2) subtraction 3) multiplication 4) division'
  sys.out'choose 1 to 4'
  choose = let.userinput'choose: '

  if choose == '1'
    sys.out /num1/ + /num2/
  eif choose == '2'
    sys.out /num1/ - /num2/
  eif choose == '3'
    sys.out /num1/ * /num2/
  eif choose == '4'
    if /num2/ == 0
      sys.out'ERROR: divide by zero'
    else
      sys.out /num1/ / /num2/
    end.if
  else
    sys.out'INVALID'
  end.if
end

let.call calc()

Part 1 - Function and welcome

fn calc();
  sys.out'welcome to calc.'

Declares function calc. Prints a greeting so the user knows the program started. No issues expected here.

Part 2 - Typed numeric input (v1.61+)

  num1 = let.userinput.int'enter number first: '
  num2 = let.userinput.int'enter number second: '

These calls capture integer values directly. On v1.61+ the returned values are numeric types suitable for arithmetic. This avoids manual parsing and reduces errors.

If you must support older runtimes, fallback example:

inputs are not support for versions below 1.60 CORE

Always validate input on user error. For `let.userinput.int`, test entering non-numeric text and ensure your runtime prompts or errors clearly. If the runtime does not auto-validate, implement a simple parse check and re-prompt.

Part 3 - Menu and choice

  sys.out'1) addition 2) subtraction 3) multiplication 4) division'
  sys.out'choose 1 to 4'
  choose = let.userinput'choose: '

Shows options and captures a selection as a string. The code compares string tokens like '1'.

Normalize input by trimming whitespace and lower-casing if needed. Prefer `let.userinput.int` for numeric choices when available: `choose = let.userinput.int'choose: '` then compare numbers.

Part 4 - Addition branch

  if choose == '1'
    sys.out /num1/ + /num2/

If the user chose option 1, the code prints the sum. Because `num1` and `num2` were captured via `let.userinput.int`, they are numeric and this prints the arithmetic result.

If you used string-based input, convert before arithmetic: num1 = tonumber(num1).

Parts 5 and 6 - Subtraction, multiplication and division guard

  eif choose == '2'
    sys.out /num1/ - /num2/
  eif choose == '3'
    sys.out /num1/ * /num2/
  eif choose == '4'
    if /num2/ == 0
      sys.out'ERROR: divide by zero'
    else
      sys.out /num1/ / /num2/
    end.if

The division branch checks the divisor before computing. Important: when comparing to zero ensure the comparison is numeric. With `let.userinput.int` this is automatic. If using parsed input, compare with the parsed numeric value.

If you need floating point division, confirm your runtime supports floats. If only integer division is supported, document that the result may be truncated.

Part 7 - Fallback and invocation

  else
    sys.out'INVALID'
  end.if
end

let.call calc()

The `else` branch prints INVALID for any other choice. The function finishes and is invoked via let.call calc(), which is supported on v1.61+. If your target runtime prefers direct calls, use calc().

Testing checklist for this example

  1. Run bolt --version and confirm v1.61 or newer.
  2. Enter valid integers and verify arithmetic results match expectations.
  3. Try invalid inputs and confirm either the typed helper re-prompts or your parse fallback handles the case.
  4. Check division by zero behavior and confirm the guard prints the error message.

If issues persist, gather the exact terminal output and the Bolt version and include them in your support request.

Safe scripting practices

Detect runtime version with bolt --version and choose typed helpers when v1.61+ is detected. For automation, avoid blocking user prompts; accept flags or environment variables to switch into noninteractive mode.

Distributing scripts

Troubleshooting

Concrete steps when Bolt is not recognized or scripts fail. No vague suggestions.

Bolt not recognized

  1. Confirm install folder exists. Windows default: C:\Program Files\Bolt.
  2. Run the executable directly from the folder: open PowerShell in the folder and run .\bolt --version. If this runs, the binary is fine but not on PATH.
  3. Add the install folder to PATH:
    • Windows: Start → Edit the system environment variables → Environment Variables → under System variables edit Path → Add the Bolt folder → Save → restart terminal.
  4. If the binary is missing or corrupt, re-download the installer from the official page and reinstall. Use the installer-provided uninstall when available before reinstalling.

Script errors or missing helpers

Confirm your runtime version is v1.61+ for typed helpers and modern control flow. If running older versions, include fallback parsing and safe guards. When requesting help provide the Bolt version, the script, and the exact terminal output.

Collect logs

Run scripts with bolt --debug --run script.blt or bolt --json-errors --run script.blt to get structured information to attach to a support request.
